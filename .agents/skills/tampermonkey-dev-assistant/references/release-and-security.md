# Release and security

## 权限与数据

- `@match/@include` 仅覆盖必要站点；避免无理由的全站匹配。
- `@grant` 和 `@connect` 与实际调用一一对应；删除权限属于独立变更，不顺手处理。
- 跨沙箱交互最小化；传入页面上下文的数据必须验证，插入 HTML 必须使用项目现有净化路径。
- 不记录或交付 Cookie、Authorization、CSRF、完整请求/响应、私信、草稿、个人资料或本地存储秘密。
- HAR、Heap Snapshot、Performance trace 和截图可能含敏感内容；默认只汇报脱敏摘要，不上传、不提交。

## 发布门槛

只有明确发布授权时执行：

1. 确认本地 `main.js` 是发布权威，调试加载器不进入正式代码。
2. 检查元数据、权限、更新地址、第三方 `@require` 版本与完整性风险。
3. 完成相关静态检查和真实浏览器功能/视觉验收。
4. 完成宿主 A/B 回归，检查请求、错误和资源趋势。
5. 按项目规则更新版本；不得为了本地调试自动提高版本。
6. 检查发布产物不包含本地 `file://`、调试标记、源码绝对路径、凭据、HAR、trace 或 Heap Snapshot。
7. 用户明确要求 commit/push 时调用 `commit-workflow`；发布到 GreasyFork 或其他外部系统需再次确认目标和可回滚性。

## 交付格式

先写结果，再写：修改文件与目标、静态检查、浏览器场景、宿主回归、请求/性能/内存摘要、未验收项、发布状态和下一动作。不得把“浏览器已打开”“MCP 已连接”写成“功能已通过”。
