# Awesome LinuxDo Reader 项目介绍

本文集中维护项目与用户手册可复用的产品介绍。当前版本：`1.5.0`。

## 一句话介绍

把 Discourse 从帖子列表，变成完整的阅读工作区。

## 简短介绍

Awesome LinuxDo Reader 是一款运行在浏览器 userscript 管理器中的 Discourse 增强阅读工具。它在保留原站账号、权限和内容来源的前提下，把长帖阅读、讨论上下文、原站互动、跨语翻译和资料整理组织到一个连续工作区。项目为 LINUX DO 深度定制，也通过运行态识别与能力检测兼容其他标准 HTTPS Discourse 社区。

## 完整介绍

Awesome LinuxDo Reader 面向频繁阅读长帖、跟进讨论和处理社区消息的 Discourse 用户。脚本将主题阅读组织为浮窗、全屏、左右嵌入或移动工作区，减少列表页与帖子页之间的往返，并保留回复、点赞、收藏、通知、搜索和用户资料等常用操作；回应、Boost、Post Voting 等插件能力会按站点实际支持情况自动显示或隐藏，因此缺少对应插件的论坛也不会留下无效入口。

阅读器围绕长内容场景提供楼层关系、楼中楼、跳转提示、浏览历史、真实已读进度、原图灯箱、媒体播放与公式渲染。通知、历史、收藏、Topic 下载、用户观察、岁月史书和不想看统一进入共享多标签工具浮窗；用户可以持续整理公开活动，也可以继续阅读服务器已返回 404、但本机仍保留正文的内容。当地日落自动暗色、不想看自动过滤、离线 Topic 和多种译文样式进一步覆盖长期阅读场景。

针对长帖和多标签页，项目使用 DOM 窗口化、分层缓存、后台集合续传、共享请求调度、429/Cloudflare 恢复和脱敏诊断，在阅读连贯性与站点负载之间取得平衡。18 个设置面板覆盖界面、阅读、快捷方式、性能、数据和同步；WebDAV 可按 12 类独立开关合并有价值的本地记录。设置 v9 导出、导入和恢复默认使用可回滚事务，翻译 API Key、WebDAV 用户名与密码始终排除；21 个快捷动作共用保留键门禁，六类缓存的危险清理会先列出类别并二次确认。

项目不接管账号体系，也不替代任何适配站点。站点数据和互动结果仍以当前原站为准；设置、阅读状态和缓存默认保存在当前浏览器，只有用户主动开启的翻译或 WebDAV 能力才访问对应外部服务。

## 产品体验

- **留在列表中阅读**：打开主题时保留宿主列表和筛选状态，在当前页面持续切换主题。
- **沿讨论关系前进**：通过父回复、楼中楼、引用、时间轴、历史和队列理解长帖上下文。
- **直接完成社区操作**：回复、点赞、收藏、通知和站点插件能力继续服从原站账号与权限。
- **把工具放在同一工作区**：消息、历史、收藏、下载、用户观察、岁月史书和不想看共用多标签浮窗。
- **按自己的方式管理数据**：设置导入导出、恢复默认、缓存清理和 WebDAV 同步相互独立，每项操作都有明确确认与回退边界。

## 业务能力全景

| 业务域 | 用户目标 | 核心能力 | 数据与联动结果 |
| --- | --- | --- | --- |
| 主题发现 | 留在列表中筛选并打开主题 | 宿主列表保留、左右嵌入、浮窗、全屏、移动布局 | 不改变原站列表状态；打开记录进入本地历史 |
| 连续阅读 | 在长帖和多个主题间稳定推进 | 虚拟阅读流、时间轴、只看楼主、历史导航、阅读队列 | 阅读位置、队列进度和预加载状态按主题持续保存 |
| 上下文理解 | 找到回复来源和讨论分支 | 父回复预览、引用回跳、楼中楼、完整讨论、已解决答案 | 楼层仍以原站编号为准，跳转后恢复精确位置 |
| 社区互动 | 不离开工作区完成原站操作 | 回复、点赞、回应、Boost、收藏、通知、分享、权限操作 | 请求提交到当前 Discourse；结果服从登录态与原站权限 |
| 内容处理 | 阅读图片、媒体、公式和非中文正文 | 原图灯箱、图片评论、下载、HLS、KaTeX、翻译与代码工具 | 原文不被覆盖；翻译只在主动启用时访问所选服务 |
| 资料整理 | 找回、归档或离线保存重要内容 | 历史、收藏、消息、用户观察、岁月史书、不想看、离线 Topic | 普通记录保存在浏览器；离线 Topic 是独立 HTML 对象 |
| 个性设置 | 让不同设备和阅读形态符合习惯 | 18 个面板、21 个快捷动作、三种形态配置、当地日落暗色 | 保存后按字段作用域生效；保留键和危险操作有统一门禁 |
| 数据治理 | 迁移配置、清理缓存并跨设备同步 | 设置 v9 导入导出、失败回滚、六类缓存、WebDAV 12 类同步 | 凭据不进入导出；缓存、设置、同步和恢复默认互不混用 |
| 稳定性诊断 | 理解慢加载、429、Cloudflare 和资源压力 | 共享调度、请求脉络、退避恢复、DOM 指标与脱敏导出 | 诊断只反映当前页面可观测状态，不宣称脚本独占资源 |

## 核心业务链路

1. 用户从主题列表打开内容，阅读器建立工作区并恢复该主题最近的阅读位置。
2. 阅读过程中，时间轴、楼层关系和完整讨论共同维护上下文；加入队列后可在多个主题间切换并继续后台准备。
3. 回复、收藏、回应和通知等互动直接调用当前原站，历史、队列进度和工具窗口状态留在当前浏览器。
4. 需要迁移时导出非秘密设置；需要跨设备延续时，再单独配置 WebDAV 并选择 12 类同步对象。
5. 遇到异常时先看请求与资源诊断，再按类别清理缓存；恢复默认只重置阅读器设置，不删除历史、队列、缓存或原站数据。

## 核心能力

- 连续阅读：列表页直接读完整帖子，支持浮窗、全屏和移动布局。
- 楼层导航：楼中楼、父回复预览、楼层跳转、时间线和浏览历史。
- 社区互动：回复、点赞、回应、收藏、通知、搜索与用户资料。
- 内容呈现：原图灯箱、图片评论、音视频播放、HLS 与 KaTeX 公式。
- 跨语阅读：在非中文内置社区和语言未知的自定义 Discourse 站点切换原文、双语和简体中文译文，可选用公共翻译或用户配置的 OpenAI 兼容模型。
- 离线阅读：按全部、楼主或自选楼层后台生成独立 HTML，支持搜索、跳转、讨论分支与本地历史管理。
- 个性设置：主题、字体、布局、窗口、动效和多种显示形态配置。
- 跨设备同步：通过标准 WebDAV 三方合并历史、收藏、设置、阅读队列和阅读位置等可选记录，也可单独启用翻译配置、译文缓存与离线 Topic 同步。
- 安全配置：组合导出、导入与恢复默认支持失败回滚，秘密凭据不进入导出文件。
- 性能治理：DOM 窗口化、分层缓存、请求预算、429 退避和资源监控。

## 适用场景

- 在主题列表中快速筛选并连续阅读多个帖子。
- 阅读楼层较多、引用关系复杂或媒体内容丰富的长帖。
- 集中处理浏览历史、收藏、消息和搜索结果。
- 希望按设备和阅读习惯调整布局、字体与性能策略。

## 运行边界

| 项目 | 当前配置 |
| --- | --- |
| 匹配站点 | LINUX DO、20 个其他内置社区、自动识别的标准 HTTPS Discourse，以及用户验证添加的深度定制站点兜底 |
| 脚本权限 | `GM_getValue`、`GM_setValue`、`GM_xmlhttpRequest`、`GM_getResourceText`、`unsafeWindow` |
| 跨域连接 | `connect.linux.do`、`credit.linux.do`、自定义站点检测、用户配置的 HTTPS WebDAV，以及用户主动启用的 Google / Microsoft 或 OpenAI 兼容翻译接口；动态目标由 `@connect *` 承载，业务端口按固定用途收窄 |
| 外部依赖 | KaTeX、pinyin-pro、hls.js（jsDelivr） |
| 数据位置 | 浏览器本地存储、Cache Storage 与 IndexedDB；用户主动配置后，普通所选记录合并到 WebDAV JSON，离线 Topic 以独立 HTML 对象保存 |
| 发布入口 | [GreasyFork 脚本页](https://greasyfork.org/zh-CN/scripts/588185-awesome-linuxdo-reader) |

LINUX DO 全面适配、标准 Discourse 社区通用的增强阅读器：列表页直接阅读完整主题，保留楼层关系与原站互动，支持跨语翻译、原图灯箱、离线 Topic、WebDAV 同步和精细布局。
