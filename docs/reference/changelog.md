## 0.1.16 — 自适应标题栏与原站状态同步升级

核验日期：2026-07-28。

### 重大特性

- 标题栏改为随阅读器宽度和界面字号连续缩放：标题、楼主、统计、分类和标签分别保留可读下限；标题可自然换行，编辑与原生页面操作会跟随首行文字对齐，浮窗、中宽窗口和窄屏不再使用同一固定字号与高度。
- 分类、标签和主题投票进入独立横向浏览区；溢出时显示左右方向提示，并支持鼠标滚轮、触控横向滑动和键盘聚焦，未溢出时自动收起提示，避免大量标签挤占标题或控制按钮。
- 阅读队列新增统一表面边界：拖动、恢复位置和响应式重排都把标题栏底部作为纵向起点；全屏桌面布局还会避让主帖操作列，在默认位置、上方或下方中选择最近的安全位置。
- 完整讨论窗口使用可恢复的分支栈：重设讨论根后，标题栏左侧按钮和 `Esc` 先逐级返回上一个分支，回到入口层后才关闭；返回时复用已加载楼层、分支路径和各层视口。
- 新增 Discourse 原站更新事件桥接：监听通知、收藏、回应、帖子创建/编辑及可用回应表情配置变化，按通知、收藏、主题、楼层和回应标签精确使缓存失效；当前主题可就地合并权威楼层并刷新可见回应。

### 修复

- 修复单条通知已读只改变阅读器徽标、未同步 Discourse 普通、高优先级、分组、总数和兼容计数的问题；“全部已读”现在原子清空同一组状态。
- 修复主题末尾连续二级回复收纳后仍保留虚拟流底部高度占位、导致末尾出现大块空白的问题。
- 修复 Discourse 对同一路由重复发送页面变化信号时多次触发主题接管的问题；接管前会比较当前宿主路由键。
- 修复原站搜索菜单中的建议、筛选或非结果链接被当作主题打开的问题；只有真实 `.search-result-topic` 或 `.search-result-post` 继续进入阅读器。
- 修复阅读器容器尺寸变化但浏览器窗口未触发 `resize` 时，标题栏、队列、主帖操作列、弹层和虚拟流未及时重算的问题；阅读器主体现在由 `ResizeObserver` 驱动同一布局同步。
- 修复回应表情注册表优先使用旧宿主缓存、站点更新允许表情后当前选择器缺少新项目的问题；首次需要时补取 `/emojis.json`，配置变化后强制刷新并保留已展开选择器。
- 修复完整讨论重设分支后关闭按钮直接退出窗口、已加载分支在返回时丢失，以及 `Esc` 与标题栏返回行为不一致的问题。

### 优化与可靠性

- 标题单行/多行密度由实际文本行框决定，加载态和 481–900 像素中宽布局保留稳定最小高度；标题区操作按钮按实际图标位置做半像素对齐。
- 标题、分类和标签的溢出提示由滚动与尺寸观察器按帧合并更新，销毁阅读器时同时取消观察和待处理动画帧。
- 队列拖动保存与运行时定位共用同一边界计算，旧的纵向比例会先限制到标题栏下方，再参与贴边和主帖操作列避让。
- 鼠标侧键 3/4 接入阅读器历史链，可直接切换更早或更新的阅读记录；阅读器打开时阻止浏览器默认后退/前进，没有对应记录时保留当前页面并显示提示。
- 原站通知变化会同时过期首屏内存缓存和持久响应缓存；收藏变化会刷新已打开面板，回应变化按帖子与主题范围更新正文、主帖操作列和收藏/回应中心。
- 从主题缓存启动后直接进入统一实时更新链路，不再额外安排一次延迟的“最新回复”刷新，减少打开阶段的重复请求与状态竞争。
- 仓库直装压缩产物预算由 950,000 字节调整为 1,000,000 字节，继续保留 400,000 字节 gzip 闸门；GreasyFork 仍发布未经压缩的可读 `work/main.js`，不使用该直装产物。
- 发布样式固定到不可变提交 `6f32c5f548d440963c1c0abb2160908b609f5aec`；本地与 jsDelivr 均为 419,911 字节，SHA-256 均为 `0738f4c1470861e1c7fcf29db5b8cb76f788896740492e2a2fc760c90691ff7e`。

## 0.1.15 — 消息中心、精确恢复与交互工作区升级

核验日期：2026-07-28。

### 重大特性

- 消息中心升级为“通知 / 私信”双模式：通知按回复、赞、@提及、编辑、链接、Boosts 和回应分别读取对应原站数据；私信支持最新、已发送、新、未读、归档和机器人聊天六类列表。
- 多源消息统一归一化发送者、摘要、正文摘录、时间、已读状态和精确目标；通知、用户动态、Reactions、Boosts 与私信主题各自分页、缓存并保留来源身份。
- 阅读历史和阅读队列从单一楼层号升级为完整锚点状态，可恢复当前楼层、滚动偏移、完整讨论分支位置与引用高亮；前进、后退、队列切换和重新打开主题都复用同一状态模型。
- 时间轴新增楼层号直达输入，可校验 `1–总楼层` 的有效范围；跳转过程等待数据取得、目标挂载和可见位置稳定后再完成，首帖、末帖和快速连续跳转使用同一目标仲裁。
- 完整讨论窗口增强分支阅读恢复：记录窗口内锚点，从历史或队列返回时恢复分支和滚动位置，关闭后回到进入前的主信息流视口；目标楼层过高时优先置于可读区域。
- 主帖操作列整合点赞与自定义回应：显示当前回应徽标，支持直接切换或取消回应，并继续同步正文副本、实时主题数据、Boost、回复、收藏和更多主题操作。
- 图片灯箱的关联评论支持补取主题楼层、评论树定位和回应交互；回应选择器增加悬停延迟、当前回应入口和状态同步，避免灯箱与正文显示不同步。
- 原生回复窗口新增独立的“关闭前再次确认”偏好；开启后，按 `Esc`、关闭或舍弃草稿需要在 1.5 秒内重复同一操作，与阅读器本体的“双击 Esc”设置分别生效。

### 修复

- 修复通知分类依赖单一 `/notifications.json` 数据、导致回应、Boost、编辑、链接或私信列表不完整的问题；不同来源现在使用各自端点和分页游标。
- 修复合成消息误写原站已读状态的问题；只有能追溯到原生通知 ID 的项目才参与标记已读，并从匹配的原生通知继承权威状态。
- 修复历史切换、队列切换和主题重开只保存楼层号，导致虚拟流偏移、完整讨论窗口或引用上下文丢失的问题。
- 修复完整讨论关闭后回到错误楼层、窗口内目标落在边缘、返回按钮找不到原入口，以及切换阅读形态后残留覆盖层的问题。
- 修复时间轴快速跳转时旧请求覆盖新目标、首帖和末帖完成条件不一致，以及手动输入无效楼层仍可提交的问题。
- 修复主帖操作列的点赞与回应状态相互覆盖、当前回应缺少可取消入口、重渲染后选择器开合状态丢失的问题。
- 修复 Boost 原生表情选择器延迟挂载、位置可能落到阅读器外或被裁切的问题；现在短时观察真实可见弹层并按当前窗口重新定位。
- 修复从搜索、用户菜单、汉堡菜单或聊天抽屉中的主题链接打开阅读器后，原生浮层仍覆盖阅读器的问题；先通过宿主关闭能力收起来源浮层，再进入主题。
- 修复标题栏部分区域误触发拖动、设置或完整讨论等临时层与拖动面冲突的问题，并补齐浮窗、嵌入和全屏形态的拖动边界。

### 优化与可靠性

- 通知与私信卡片新增两行正文摘录、来源状态和更细的语义图标配色；模式标签与分类标签按可用宽度均分，键盘焦点和窄屏布局保持可见。
- LINUX DO Credit 面板改为紧凑的资产、额度和状态指标，并提供首页、活动、积分与设置快捷入口；危险或异常指标使用独立状态色。
- 默认普通布局调整为 0% / 88% / 0% / 8% / 4%，正文默认字号调整为 95%；只影响尚未保存对应自定义值的新配置。
- 字体平滑、结构色开关、颜色滑块和预设色改用稳定的状态属性与 CSS 变量，减少反复写入行内样式及主题切换残留。
- 阅读队列、主帖操作列、历史按钮、标题栏和弹层位置统一在容器变化后重算；空队列、贴边收纳和短高度窗口减少遮挡。
- 十种加载动画的结构样式集中到静态资源，补齐减少动态效果下的静态呈现，降低运行时重复样式生成。
- 新增 GreasyFork 拆分工作区，可重复生成并校验主脚本模板、Core Library、JSON 静态资源和 SVG 图标资源；当前正式脚本仍保持单文件发布，拆分产物不自动替代线上入口。
- 发布样式固定到不可变提交 `90b37ad87f7a234bfb9ff76db1d59768be9652e9`；本地与 jsDelivr 均为 414,318 字节，SHA-256 均为 `1d6e0c2c43fb87bde684fe978d3a13a414a6e7d216299e53a291193ddf24eef9`。

## 0.1.14 — 设置中心、完整讨论与已读链路升级

核验日期：2026-07-27。

### 新增特性

- 设置中心从旧的 13 个平铺面板调整为 14 个面板，按“显示与布局”“阅读与交互”“系统与数据”分组；新增设置搜索、无结果提示和底部“保存全部更改”，可一次提交图片、字体、布局、浮窗、外观与跳转提示草稿。
- 新增主帖快捷操作列，集中提供回顶、点赞、回复、Boost、收藏和更多主题操作；支持长按拖动、位置记忆、锁定、恢复默认、贴边收纳和与历史按钮避让。
- 新增二级回复“完整讨论”窗口：递归加载后续分支、显示回复路径与关系线，支持分支重设、返回上层、实时回复合并、目标跳转、拖动缩放，并记住窗口几何和各分支阅读位置。
- 二级回复在主楼层列表中可收纳为参与者头像标记；点击头像仍能打开对应讨论并定位，不影响时间轴、跳转和已读状态。
- 用户信息新增 LDC 标签，只读展示可用余额、社区余额、今日额度、积分收支和支付账户摘要；校验 LINUX DO/LDC 用户名，支持 30 分钟同账号成功缓存和授权失效提示。
- 阅读与导航新增“队列为空时仍显示入口”和“双击 Esc 关闭阅读器”；帖子与回复新增主帖操作列、完整讨论和楼层收纳开关。
- 超过 10 行的代码块默认折叠为前 10 行，新增展开/收起按钮，并在收起时保持当前楼层和滚动锚点。

### 修复

- 修复 Safari/WebKit 下 Connect 或跨站会话请求未带正确分区信息的问题；仅在 Safari 路径补充顶层站点分区参数，不改变 Chromium、Firefox 等浏览器请求。
- 修复原生回复编辑器打开时滚轮事件可能落到宿主或阅读器错误滚动层的问题，并补齐阅读器内向上滚动到顶的处理。
- 修复二级回复目标从消息、历史或楼层链接进入时仍落到隐藏正式楼层的问题；目标现在优先进入完整讨论或对应父回复上下文。
- 修复完整讨论内父楼预览、返回位置、楼层号跳转和滚动根错误；空的楼层预览不再保留无内容浮层。
- 修复完整讨论的分支按钮依赖 Boost 入口、在不支持 Boost 或无权限时消失的问题；现在会依次靠 Boost、回复或点赞中的首个可用操作显示。
- 修复长代码块展开后改变虚拟流高度、收起时造成阅读位置跳动的问题。
- 修复主帖操作列与正文副本之间点赞、Boost、收藏和实时主帖数据不同步，以及虚拟流重新挂载后快捷按钮缺失的问题。
- 修复交替楼层背景与跳转高亮互相覆盖、隐藏回复前后分隔线重复、颜色设置中文标签拥挤等视觉问题。
- 修复空阅读队列仍显示数字 `0`、无法从入口直接关闭，以及队列预加载误处理当前主题的问题。
- 修复通知缺少可解析展示链接时退回通知列表、无法打开目标主题或精确楼层的问题；现在会从通知本体和 `data` 中依次读取主题与楼层编号并重建地址。
- 修复通知目标只依赖单一展示链接、同主题点击仍重新创建阅读器的问题；现在同时读取 Discourse 展示模型、`post_url/topic_url/url` 和通知字段，并优先在现有时间轴直接跳转。
- 修复用户 Flair 仅引用页面 SVG 符号、符号不可用时显示空徽章的问题；现在安全内联可用图标，失败时回退到内置盾牌。
- Cloudflare 验证失败或提交异常时统一关闭验证浮窗、释放租约并保留楼层未读，避免残留窗口和重复触发。

### 优化与可靠性

- 已读上报改为正文成功预加载后的统一候选入口：先在当前会话显示乐观已读，再按显式目标、可见楼层和后台候选的优先级排序；单次最多提交 20 层。
- `/topics/timings` 新候选立即调度，不再额外等待固定 15 秒；保留 60 秒成功指纹去重、`navigator.locks` 跨标签串行化和 Discourse 原生 screen-track 抑制。
- 请求失败后保留待确认楼层并延迟重试；只有服务器确认后才写入权威 `read` 状态和持久缓存，乐观显示不冒充服务器确认。
- 将请求记录与性能记录合并为“日志记录”面板，统一“原站”“二级回复”“页面元素”等用户术语，同时保留原有 10 秒/60 秒账本、P95、趋势和脱敏边界。
- 为现有 LDC 只读账户请求补充显式 `@connect credit.linux.do` 声明，使 userscript 权限元数据与实际跨域目标一致。
- 普通（嵌入/浮窗）与全屏改为分别保存布局：普通新默认值为 0% / 90% / 0% / 6% / 4%，全屏为 15% / 70% / 5% / 8% / 2%；打开设置时自动载入当前形态，恢复默认和统一保存也只作用于该形态。
- 配置导入兼容尚未包含独立全屏布局字段的早期 0.1.14 导出文件，并为其补入全屏默认值；其他字段完整性与版本校验保持不变。
- 新配置默认按一次 `Esc` 关闭阅读器；需要防误触时仍可开启“按两次 Esc”，已有明确保存值继续沿用。
- 新配置的正文图片比例默认值调整为 50%，加载动画默认改为“引文回声”；已有有效用户设置继续保留。
- 新配置的宿主列表标题、头像、统计和标签卡片默认尺寸调整为 110%、80%、120% 和 100%，阅读器正文默认字号调整为 98%；已有有效用户设置继续保留。
- 阅读队列、主帖操作列和设置窗口按当前容器重新计算碰撞与可用位置，减少窗口缩放、窄屏和拖动后的遮挡。
- 全屏标题栏按正文左右边界对齐，阅读队列入口跟随主帖操作列收纳按钮的横向中心；布局、窗口或操作列位置变化后同步重算。
- 通知卡片为具体通知类型选择语义图标，并按回复、点赞、Boost、关注、私信和其他分类显示不同圆形强调色，减少图标与标题拥挤。
- 完整讨论中的父回复入口改为蓝色提示块，当前楼层号独立靠右；跳转高亮仅作用于入口图标，并为减少动态效果提供静态提示。

## 0.1.13 — 通用适配与诊断链路精简

核验日期：2026-07-26。

- 统一内置 Discourse 站点适配器的构造方式，保持 LINUX DO 专属能力声明与其他社区的自动降级逻辑不变。
- 正文翻译同时收集普通楼层内容与已解决摘要，跨语阅读时不再遗漏解决方案卡片中的正文。
